# Rule Set: Design Documents

Scope examples: `design/**`, `docs/design/**`, ADRs, architecture notes.

## Rules
- State assumptions and constraints explicitly.
- Present alternatives when tradeoffs are meaningful.
- Explain selected approach and why.
- Describe impact on interfaces, operations, and maintenance.
- Include verification and test considerations.

## Suggested sections
- Context
- Constraints and assumptions
- Alternatives
- Decision
- Impact
- Verification approach
